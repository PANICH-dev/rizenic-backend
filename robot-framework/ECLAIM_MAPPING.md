# JSON → ใบรับรถ E-Claim

โหมดนี้กรอกฉบับร่างเท่านั้น **ห้ามบันทึก** และไม่มี keyword บันทึกใบรับรถ ปิดปุ่ม `bntSave` ป้องกัน Enter และบล็อกการ submit ยกเว้น postback สำหรับเลือกบริษัทประกัน/สถานะจอดซ่อม ซึ่งใช้เปิดช่องกรอกของหน้า Web Forms

## ผลตรวจฐานข้อมูล local วันที่ 23 กันยายน 2026

ตรวจแบบ read-only งาน 1081 และ 1082 ใน `rizenic_new`:

| ข้อมูล | สิ่งที่พบ |
|---|---|
| ลูกค้า | customer_id 1005 มีชื่อและ PHONE 0810000000 ไม่มีข้อมูลที่อยู่/บัตรประชาชนสำหรับงานนี้ |
| รถ | vehicle_id 1031, Tesla Model 3, VIN และทะเบียนตรงกับ JSON แต่ plate_province ว่าง |
| ประกัน | master มี INS-01 “ชับบ์” แต่ repair_jobs.insurer_id ว่าง มีเพียง payment_label |
| สถานะจอด | JSON เป็น “จอดซ่อม” แต่ repair_jobs.is_parked เป็น NULL |
| วันซ่อมเสร็จ | JSON เป็น 2026-09-28 แต่ actual_finish_on และ repair_finished_on เป็น NULL |
| การนัดหมาย | appointment_on เป็น NULL; intake_on 2026-09-24, target_finish_on 2026-09-28, delivery_on 2026-09-29 |
| ใบตรวจสภาพ | ไม่มี inspections สำหรับทั้งสองงาน จึงไม่มี fuel_percent/inventory ให้เติม |
| การเงิน | ไม่มี job_financial_summaries สำหรับทั้งสองงาน; ค่าแรง 2,500 อยู่ใน JSON eclaim.items |
| เอกสาร | มี CLAIM, QT, SO; ไม่มีเลขกรมธรรม์หรือเลขรับแจ้งแยกต่างหาก |

`RobotOutboxService` เขียน payload ที่ frontend ส่งมาโดยตรง ไม่ดึงข้อมูลประกอบจาก DB จึงไม่ใช่ snapshot ของ DB ที่ตรวจความสอดคล้องแล้ว และไม่สามารถใช้เติมข้อมูลที่ขาดเองได้ การตรวจครั้งนี้ไม่ได้แก้ฐานข้อมูลหรือ backend

## การจับคู่ที่ใช้

| JSON | ช่องปลายทาง |
|---|---|
| customer.payment หรือ eclaim.insurer_id | บริษัทประกัน |
| workflow.park_status | จอดซ่อม/ไม่จอดซ่อม |
| vehicle.plate / vehicle.vin | ทะเบียน / หมายเลขตัวถัง |
| eclaim.province | จังหวัด; กรุงเทพมหานคร → กรุงเทพ ฯ |
| documents.claim_no | เลขที่เคลมเท่านั้น ไม่คัดลอกไปเลขรับแจ้ง |
| documents.notification_no / policy_no (ถ้ามี) | เลขรับแจ้ง / เลขกรมธรรม์ |
| customer.name / phone | ผู้ติดต่อ / มือถือ ถ้าช่องเปิดให้กรอก |
| inspection.customer_name / phone / mileage | ผู้นำรถเข้าซ่อม / มือถือ / เลขไมล์ |
| customer.landline / address / id_card / email / line (ถ้ามี) | ช่องที่ตรงกันและเปิดให้กรอก |
| eclaim.items ประเภทที่ระบุ “ค่าแรง” | ผลรวม qty × unit_price เป็นประมาณค่าแรงซ่อม |
| repair.parts | มี/ไม่มีรายการอะไหล่ |

ชื่อประกัน “ชับบ์” กำกวม: E-Claim มีรหัส 2418 สำหรับ “บริษัท ชับบ์สามัคคีประกันภัย จำกัด (มหาชน)” และ 15 สำหรับรายการ `(L)` ส่วน DB มี INS-01 ซึ่งเป็นรหัสภายใน ห้ามถือว่าเป็นรหัสเดียวกัน ควรส่ง `eclaim.insurer_id` หรือรหัสใน `insurance.code` ที่ตรงกับ E-Claim จริง หรือระบุ `--variable ECLAIM_INSURER_ID:2418` เมื่อยืนยันตัวเลือกแล้ว หากไม่มีรหัส ชื่อต้องตรงเพียงตัวเลือกเดียวจึงจะกรอกต่อ

## ข้อมูลที่เว้นไว้

- ไม่กรอกเลขบัตรประชาชน ที่อยู่ เชื้อเพลิง หรืออุปกรณ์ติดรถ หากไม่มีข้อมูล; `null` ไม่เท่ากับ “ไม่มี”
- เบอร์ใน JSON เป็นมือถือ จึงไม่คัดลอกไปสร้างเบอร์โทรศัพท์พื้นฐานที่ไม่มีข้อมูล
- ชื่อพนักงานของ E-Claim ใช้ค่าปัจจุบันของระบบ ไม่แทนด้วยชื่อผู้ใช้ทดสอบ local
- รุ่นรถต้องเลือกจาก catalog จริงและได้รหัสภายในด้วย ไม่เขียนทับ label แบบ read-only เพื่อแกล้งให้ดูว่าจับคู่สำเร็จ
- ระดับ “เบา” ไม่เพียงพอที่จะเลือก Q1/Q2; ต้องมี mapping ประเภทงานซ่อมที่ยืนยันแล้ว
- วันที่ระบบสร้างและช่องปฏิทินยังคงเดิม ไม่เอาวันเข้าจริงไปแทนวันนัด หรือวันส่งมอบจริงไปแทนวันนัดรับรถ
- ตารางรายการอะไหล่/ประเมินราคาและ QT/SO/BL ไม่มีช่องแยกบนใบรับรถ ไม่ยัดลงช่องที่ความหมายต่างกัน
- ช่อง “ความเสียหายอื่น ๆ (ไม่รวมอยู่ในรายการซ่อม)” ไม่ใช่ช่องหมายเหตุทั่วไป จึงไม่คัดลอก workflow.notes ลงไป

ผลจริงแต่ละรอบอยู่ใน `results/.../intake-fill-report.json` มีรายการ filled/skipped/assumptions พร้อมภาพ `intake-filled-unsaved.png` เทสต์ผ่านหมายถึงกรอกและตรวจค่าที่จับคู่ได้ ไม่ได้หมายถึงครบทุกช่องบังคับหรือพร้อมบันทึก
